## Steps

1. **Analog clusters** (`model/analogs/build_analogs.py`): cluster the 13,471 cells with k-means (try k between 12 and 30, pick by silhouette with a fixed seed, report the choice) on standardized features from the grid: `rain_mm_yr`, `rain_cv`, `rain_p25_mm`, `heavy_days_yr`, `frost_free` length, `hot_days_gt35`, `bare_soil_days_yr`, soil texture classes and `soc_g_kg` when present, latitude. Handle nulls with median imputation and record the imputed share per feature. Keep the cluster labels stable across runs.
2. **Cluster labels**: for each cluster a short neutral-Spanish label built from the cluster means by a small template (for example "húmedo, sin heladas largas, suelo franco"), and `n_cells`. No free-form text.
3. **MAGyP crops per analog** (Argentina): download the official "Estimaciones Agrícolas" CSV from datos.gob.ar (search the portal; use the latest campaign, department level). Map departments to cells with a department boundary from Natural Earth or IGN (a cell takes the department of its centroid). For each cluster, aggregate planted area share and mean yield (kg/ha) by crop for soja, maíz, trigo, girasol, sorgo. If the dataset cannot be downloaded unattended, write the exact URL and the blocker in the report and leave `ar_crops` empty.
4. **Output** `data/processed/field/analogs/{h3_r2}.json` in the shape of `fixtures/field/analogs/82c2effffffffff.json`: per cell `cluster`, `label`, `n_cells`, `ar_crops` (`crop`, `share`, `yield_kg_ha`, `src`). Validate with `python back/tools/validate_contract.py data/processed`.
5. **Wire into `/api/field/rotations`**: when the analog shard exists for the plot's cell, add one evidence item per strategy of the form `{text, indicator: "analogs", source}` using real numbers (for example the area share and yield of the strategy's main crop in analog zones), and remove the matching entry from `gaps`. Add tests with a synthetic shard and update `back/README.md`. Files are read through the same data service as `risk/` and `field/grid` (`DATA_BASE_URL`, `file://` for local runs).
6. **R2 uploader** (`pipeline/upload_r2.py` already exists from Ezequiel: read it first and reuse its conventions if compatible; otherwise write `tools/upload_r2.py`): upload a local folder to a Cloudflare R2 bucket through the S3 API (`boto3`, endpoint `https://<account>.r2.cloudflarestorage.com`), reading `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET` from the environment or root `.env`. Features: `--dry-run` by default (prints counts and total size), `--prefix v1/`, content types for `.json` and `.csv.gz`, `Content-Encoding: gzip` for pre-gzipped JSON if applicable, `Cache-Control: public, max-age=3600`, parallel uploads (16 workers), skip objects whose size and MD5 match, resume safe. Add tests with a stubbed S3 client. Do not run a real upload.
7. **Folder mapping doc** in `tools/README.md`: which local folder goes to which R2 prefix (`data/processed/field/grid` to `v1/field/grid`, `data/processed/field/analogs` to `v1/field/analogs`, `data/processed/risk` to `v1/risk`, Ezequiel's export to `v1/`), and a note that Ezequiel's `risk/` historial shards and Devin's `clima` shards share the same paths, so the Argentine `clima` shards must be uploaded last.
