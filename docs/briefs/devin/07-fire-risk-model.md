# Devin task 07 — Fire risk model for Argentina (one long unit)

Start after task 06 finishes. Read first: `docs/data-contract.md` sections 2.6 (`risk/`) and 5, `docs/decisions.md` D7, D8, D12, and the `risk` fixture `fixtures/risk/82a967fffffffff.json`. Inputs already on disk (do not regenerate): `data/processed/model_input/fires_ar_r5_daily.parquet` (746k rows, 11,141 cells with fire, 2012-01-20 to 2025-12-31, VIIRS detections per cell and day; it ends in 2025) and `data/processed/model_input/power_ar_daily.parquet` (POWER daily weather on a 0.5 x 0.625 degree grid, 2012 to 2026-11-12). Do not modify `docs/` or `fixtures/`. Do not commit. Secrets only from the environment; never print them.

## Goal

For each H3 res-5 cell of Argentina, the probability of at least one VIIRS fire detection in the next 7 days, with a climatology baseline the model must beat on the 2023 to 2025 hold-out, and the output files for the web.

## Steps

1. **Cell universe**: all Argentina res-5 cells (reuse the polyfill from task 06 if it exists under `data/`, else polyfill a Natural Earth admin-0 boundary). Cells absent from the fires file have zero fires.
2. **Dataset** (`model/fire_risk/build_dataset.py`): one row per cell and week-start date (weekly steps, Monday), 2012 to 2025. Label = 1 if the cell has at least one detection in the following 7 days. Map each cell center to its nearest POWER grid point. Features, all computed only from data before the row date (no leakage): fires in the cell in the last 7, 30 and 365 days; fires in the 8 neighbor cells (H3 ring 1) in the last 30 days; sine and cosine of week of year; latitude and longitude; POWER: mean `T2M_MAX`, mean `RH2M`, max `WS2M` over the last 7 days, rain sum over 7, 30 and 90 days, days since last rain above 1 mm; cell climatology = share of years in 2003 to 2022 with at least one fire in that week of year (computed only from years before the row date for training rows; document that choice). Write to `data/processed/model_input/risk_train.parquet`. Report row count and positive rate.
3. **Baselines and split**: temporal split only: train 2012 to 2021, validation 2022, test 2023 to 2025. Baselines on test: (a) climatology, (b) persistence rule `clim x (1 + 2A + B)` capped at 0.95, where A = fire in last 7 days and B = fire in last 30 days (this is the rule the pipeline uses for the worldwide level).
4. **Model** (`train.py`): LightGBM binary, class weighting for imbalance, early stopping on validation. Metrics on test for the model and both baselines: ROC-AUC, PR-AUC, Brier score, calibration curve (10 bins), plus the metrics split by season (southern summer, winter). Save `model/fire_risk/model.txt` and `model/fire_risk/report.md` with the table, calibration plot (PNG next to it), SHAP summary, and an honest verdict: if the model does not beat the better baseline on PR-AUC and Brier, say so plainly.
5. **Categories**: `ratio = p / clim` (null when `clim < 0.01`); `cat` bajo (<0.75), moderado (0.75 to 1.5), alto (1.5 to 3), muy_alto (>3); when `clim < 0.01`, derive `cat` from `p` alone with documented cut points.
6. **Reasons**: for each prediction, the top 2 or 3 SHAP features translated to neutral Spanish phrases from a small template table (for example "23 días sin lluvia", "humedad relativa 28 %", "focos en las celdas vecinas", "temporada de quemas"), as in the fixture.
7. **Prediction** (`predict.py`): needs the last 30 days of fires, which the Parquet does not have (it ends 2025-12-31). Fetch them from the FIRMS area API (`FIRMS_MAP_KEY` from the environment; max 5 days per request with an optional start date; sources VIIRS_NOAA20_NRT, VIIRS_SNPP_NRT and, where available, SP products; keep VIIRS `n` and `h` confidence; bbox of Argentina) and aggregate to cell-day. Fetch POWER for the last 120 days from the Zarr store as in `model/power/fetch_power.py`, or reuse the existing Parquet if recent enough. Write `data/processed/risk/{h3_r2}.json` for every res-2 shard of Argentina in the contract shape: `generated_at`, `horizon_days: 7`, cells with `p`, `clim`, `ratio`, `cat`, `level: "clima"`, `model_version`, `reasons`. Run it once and report the time it takes.
8. **Wire the back** (`back/`): nothing to change in `/api/risk` if the shape matches; confirm with a test that loads one produced shard through the existing endpoint code, and run `python back/tools/validate_contract.py data/processed/risk`.
9. **Tests** (`model/fire_risk/tests/`): no feature uses data after the row date (construct a synthetic cell where a fire appears only after the row date and assert the features stay zero); category boundaries; reasons never empty; output validates against the contract.

## Report

Row count and positive rate; test-set table for model versus both baselines (ROC-AUC, PR-AUC, Brier); the honest verdict; top 5 SHAP features; runtime of training and of `predict.py`; the risk object for the Pergamino cell (`85c2e8bbfffffff`) and the Corrientes cell (`85a963c3fffffff`); validator output; anything the data lacked.
